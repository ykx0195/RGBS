## 保持一致的条件

- 沿用前一实验的实际 GPTCache 0.1.44、SQLite、FAISS Flat、Top-1、显式原始余弦评估器及正常 `adapt` miss-only 更新回调。
- 编码器为论文 BGE-small-en-v1.5、CLS pooling、L2 归一化；复用模型和来源核验过的冻结 Test 向量，以及上轮已冻结的最终候选向量。本轮没有新增编码或修改向量，没有测在线编码延迟。
- 候选文本、顺序和预算都来自上轮冻结记录，没有重新搜索、改写、重新选句、调整阈值或用 Test 选顺序。
- 每组从空共享缓存开始，组内不清空缓存、不强制 miss、不 direct put、不指定任意答案。
- 仍由 Qwen3.8 Flash 在正常 miss 时提供自然语言答案，system prompt、temperature=0、max_tokens=384 均不变。完全相同的生成请求可以复用已经保存的真实 API 回答，并逐次记录重放。
- Test 阶段固定缓存，不新增条目；未命中不调用答案模型。本轮测量实际缓存命中/返回覆盖，不测未命中回答质量。

## 去标识化范围

沿用同一个占位符保持及已知合成字段注册表规则。直接占位符输入和合成字段原文输入均由服务的预处理回调处理；没有手动改动编码器处的输出。

合成字段条件是已知字段的受控转换，不代表任意自动 PII 检测器都能得到同样的文本，也不是 Presidio 验证。这里确认的是明确配置参考服务中的可提交性与准入结果，不宣称任意生产部署兼容。

## 独立核对

1. 新集合与上一轮冻结文件的 SHA-256 一致，所选向量和句子顺序保持不变。
2. 所有候选句对的 float32 内积与 float64 归一化余弦均严格小于 0.85，无容差放宽。
3. SQLite 实际保存的问题文本和顺序与准入事件逐项一致，分别为 15、5、10 条。
4. 每次写入的回答可追溯真实 API 请求、响应及哈希；所有提交均为 miss，不存在提前命中后强制写入。
5. Test 评价前后条目数量保持不变；6,110 次实际检索逐条与实际入库键的独立阈值 oracle 一致。
6. 实际返回的答案来自保存的入库回答，覆盖数精确复现 1,083、305、909。
7. 服务器验证脚本通过；结果下载后在本机再次执行同一脚本，也通过。

本轮新增真实回答 API 调用 12 次，复用真实响应 48 次，其中 18 个不同响应来自上一轮保存记录；最终共保存 30 个不同文本的回答。没有新的 RKGB 文本生成搜索、梯度优化或任务评判。

## 论文使用边界

本轮补足了“该重选集合在指定参考服务中可以按顺序通过正常入口全部入库，并达到相同覆盖”的实测证据。不涉及正常背景条目竞争、TTL/淘汰、不同生产脱敏器、附加业务准入校验或答案正确性。不能直接把这些命中率写成错误答案复用率。

正文尚未修改。若后续使用新的主文本集合，应同步主结果及其原文/脱敏对照、图表和任务审计，不能直接把原集合的跨任务标签或答案适用性结论赋给新集合。
